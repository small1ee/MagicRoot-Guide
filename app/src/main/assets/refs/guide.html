安卓 Root 使用者指南（实操版）

与主手册的分工：《安卓 Root 实战手册 v1.2》讲「生态为什么长这样」；本册讲「我要干什么 → 装什么 → 出问题怎么办」。 适用：已 root 或准备 root 的用户 ｜ 专项：荣耀 8E5 / Magic8 Pro（假回锁 + FinaSU 实测路径） 快照日：2026-10-29。生态每月都在变，装机前请核对各项目 Release。
先分清楚两件事（全册都按这个模型讲） 「怎么拿到 root」：解锁刷内核（永久）／ 漏洞提权（临时）——这是手段。 「root 是哪一家」：Magisk / KernelSU 系 / APatch 系——这是分支，由内核里跑的那份实现决定。 所以「临时 root」不是一个分支，用它提权后接管的是内核里那份 .ko，装哪家管理器都不改变分支。

1. 动手前，先量三件事（3 分钟）

把下面三条跑完，后面所有决策才有依据，不要跳过。

# ① 内核里到底有没有 root 实现？
adb shell su -c "ls /data/adb/ksu /data/adb/magisk /data/adb/ap 2>/dev/null"
adb shell su -c "ksud -V" 2>/dev/null || echo "不是 KernelSU 系"

# ②  bootloader 锁没锁？
adb shell getprop ro.boot.flash.locked      # 1 = 锁定
adb shell getprop ro.boot.vbmeta.device_state  # locked / unlocked

# ③ 内核接口版本（刷任何内核级东西前必看）
adb shell uname -r      # 形如 6.12.58-android16-... → KMI 是 android16-6.12
结果 你属于 能装持久化模块吗
有 /data/adb/ksu 或 magisk 或 ap，且 BL 已解锁 永久 root ✅ 装完重启即生效
有 root 但 BL 锁定（漏洞提权，每次开机重来） 临时 root ⚠️ 只能靠软重启，见 5.3
BL 显示 locked，但 /data/adb 是持久的、重启还在 假回锁（永久） ✅ 与真解锁等效
什么都没有 还没 root 先解决 root

一句话判据：模块挂载发生在开机阶段；物理重启后 root 就没了 = 模块永远挂不上。这是临时 root 一切麻烦的根源。

2. su 管理器选型（本册重点）

配套图：同目录 su管理器选型决策图.svg —— 三个问题定位到分支，并列出「选完之后必做的第一步」。 记不住表就记这句：要元模块的分支，先装元模块；要 Zygisk 的分支，先装 Zygisk 实现。

读表口诀：

  1. "要元模块吗"列 = ✅ 的，装任何功能模块之前，先把元模块装上。 不装 = 装了完全不生效（第一大玄学）。
  2. "要另装 Zygisk 吗"列 = ✅ 的，装 LSPosed/Vector 之前，先装 Zygisk Next 或 ReZygisk。
  3. KPM 只有 3 家能做：SukiSU / BakaSU / APatch 系。SUSFS 只认 KSU 系 + 打过补丁的内核。

2.2 三条互斥铁律（违反必翻车）

  1. 一个内核只能有一套 root。 Magisk 与 KernelSU 系、APatch 不能共存。
  2. 管理器与内核必须同分支同版本协议。 跨分支装管理器 = 永远显示「未安装 / 不支持」。
  3. Zygisk 实现只能有一套。 内置引擎（FolkZygisk / YukiZygisk）与外挂（ZN / ReZygisk / NeoZygisk）二选一，双开会互相抢注入。

2.3 分支速查卡（一张卡看懂一个分支）

🟦 Magisk 官方

  • 选它：第一次玩、要最全的 Zygisk 模块生态、要最多教程
  • 装完第一步：设置里打开 Zygisk
  • 别装：任何"元模块"（Magisk 没有这个概念）
  • 隐藏路线：Zygisk Assistant → PlayIntegrityFork

🟩 KernelSU 官方

  • 选它：想要干净的内核级实现、看得懂文档
  • 装完第一步：先装 meta-overlayfs（元模块），再谈别的
  • 之后：Zygisk Next / ReZygisk → 功能模块
  • 别装：KPM 内核模块（不支持）

🟩 KernelSU-Next

  • 选它：想要 KSU 的能力又不想管元模块（自带挂载引擎）
  • 装完第一步：直接装 Zygisk 实现 → 功能模块
  • 配 SUSFS 补丁内核可上内核级隐藏

🟪 SukiSU-Ultra

  • 选它：要 KPM 内核模块 或 SUSFS 内核级隐藏
  • 装完第一步：Zygisk 实现 → 功能模块（挂载引擎自带）
  • 心理预期：功能最全，稳定性口碑一般，出问题要有自己查的觉悟

🟪 BakaSU（原 ReSukiSU）

  • 选它：老机型、求稳、要多管理器互通
  • 装完第一步：装元模块
  • 支持 KPM；Tag 多为 pre-release，别追最新

🟧 FinaSU

  • 选它：想「一次装完」——内置 FolkZygisk + Sui（Shizuku API）+ 挂载引擎 + 隐藏开关
  • 装完第一步：确认挂载后端（automatic / built-in / metamodule only / NoMount / off）
  • 默认 automatic 就好；"内置引擎 + 元模块"双开 = 卡启动
  • 最大的坑：授权是白名单，不弹窗。 新 App 要 root 必须手动加白名单
  • 别再装：Zygisk Next、ReZygisk、Shizuku、Sui、meta-overlayfs（全都内置了，装了抢服务）
  • 荣耀 8E5 上已实测可用：假回锁（保留 locked 外观）后装 FinaSU 管理器即可接管，见 6.3

🟥 APatch

  • 选它：不想编译内核、又想要 KPM
  • 装完第一步：设好 SuperKey（忘了 = 管理器进不去），再装 APM 模块
  • 不支持 SUSFS

4. 常见目标 → 具体做法

4.1 我想去广告

1. Magisk：设置 → 开启 Systemless hosts → 装 AdAway
   KernelSU 系：装 systemless hosts 模块 → 装 AdAway
2. 重启（临时 root 用软重启）
3. AdAway 里更新规则 → 看广告是否消失

验证：adb shell cat /system/etc/hosts 里有一堆 0.0.0.0 条目。

4.2 我想删预装

adb shell pm uninstall --user 0 <包名>     # 临时 root 也能用，但重启后恢复
adb shell pm disable-user --user 0 <包名>  # 更温和，能恢复
adb shell pm enable <pkg>                  # 恢复被停用/被 disable 的包（含管理器本体）
adb shell pm path <pkg>                    # 查 APK 路径，判断 manager.apk 是否装了

查包名：adb shell cmd package query-activities -a android.intent.action.MAIN -c android.intent.category.LAUNCHER --brief

⚠️ 别删：com.android.systemui、com.google.android.gms、任何带 honor/hihonor 的系统核心组件。

4.3 我想让银行/支付 App 能用

按顺序加变量，每加一项就重启 + 复测，出问题回退上一步：

① 管理器隐藏包名（管理器设置里改）
② 装 Zygisk Assistant → 把目标 App + Google Play 服务 + GMS + Play 商店加入 DenyList
   （用 Zygisk Assistant 时要关掉 Magisk 的 "Enforce DenyList"）
③ 装 PlayIntegrityFork（指纹失效会突然不过，及时更新模块）
④ 仍不过 → Hide My Applist
⑤ 仍不过 → Tricky Store

先量后治：用 Play Integrity API Checker 看三项。

  • BASIC ✅ / DEVICE ✅ / STRONG ❌ → 这是正常上限，别再折腾 STRONG（它依赖未被吊销的硬件 keybox，解锁 BL 后基本拿不到）
  • DEVICE ❌ → 修 PIF + 清 GMS/Play 商店数据

⚠️ 即使全过，银行条款通常禁止在改机环境使用，出现纠纷可能不予赔付。高价值操作用第二台未 root 的机器。

4.4 我想装 Xposed 模块

① Magisk：开 Zygisk ｜ 其他：装 Zygisk Next 或 ReZygisk ｜ FinaSU：启用 FolkZygisk
② 重启 → 装 Vector（LSPosed 的继任者）
③ 重启 → Vector 里勾选模块 + 勾作用域（目标 App）
④ 强停目标 App 再打开（进程没重启 = 模块不生效）

Vector 打不开/不注入时：见 5.4。

4.5 我想用内核模块（KPM）

先确认你的分支：只有 SukiSU-Ultra / BakaSU / APatch 系 能加载 KPM。

1. 确认内核开了 CONFIG_KPM
2. 管理器内加载 .kpm，或用 APatch 的 SuperKey 流程
3. 重启 → lsmod 看是否加载

⚠️ 内核模块搞错 = 不开机，刷之前一定备份 boot / init_boot。

4.6 我想改界面或性能

先自查 ROM 类型：

ROM 结论
类原生/Pixel/LineageOS Iconify、PixelXpert 这类能用
MagicOS / MIUI / ColorOS / OriginOS SystemUI 被厂商重写，装了也白装

省电类（GMS Doze）、音效类（JamesDSP）通用性较好，可以试；一次只装一个，装完重启测一天。

4.7 我只是想要 Shizuku 那类能力

  • FinaSU 用户：内置 Sui，别再装 Shizuku App（会抢服务）
  • 其他：装 Shizuku App，或装 Sui 模块

5.2 开机卡死：四级自救（按顺序，别跳级）

级别 操作 说明
L1 安全模式 开机按音量下，或 su -c "touch /data/adb/ksu/.safe_mode" 还能进系统/能 adb
L2 禁单个模块 touch /data/adb/modules/<id>/disable 知道元凶时用
L3 全禁 Magisk：adb shell magisk --remove-modules；其他：把 /data/adb/modules 改名 不知道元凶
L4 回刷镜像 fastboot flash init_boot init_boot_stock.img 用你备份的那份

⚠️ 不要"恢复出厂"救砖：会连加密密钥一起销毁，问题没解决还多丢一次数据。

5.3 为什么我重启后模块就没了（临时 root 必读）

  • 模块挂载在开机阶段发生；物理重启后内核回到原厂，root 消失 → 挂载永远不发生。
  • 唯一解法：软重启——只重启 Android 框架，不重载内核，让 init 重放开机阶段：

```bash

su -c "ksud soft-reboot"

```

  • 限制：① 老版本 KSU 的软重启不会重放 boot 阶段（那种构建无解）；② 依赖真实重启的模块（改 init/thermal 的）软重启后仍不完整；③ 每次开机都要重来——提权 → 模块（文件还在，不用重装）→ 软重启。

5.4 Vector 打不开或不注入

  • 首要原因（2026-11-05 真机核实）：先按下面三条排查，别急着禁用/启用模块。
    • ① 管理器本体缺失：发布包 zip 内含 manager.apk（org.lsposed.manager，带 launcher Activity 的 UI 本体）与 daemon.apk（org.lsposed.daemon，零 Activity 的后台连接器）。只装了 daemon 且被 pm disable、没装 manager 时，框架虽已注入，点 LSPosed 图标/启动按钮仍进不去界面，与框架本身无关。Vector 管理器包是 org.matrix.vector.manager。排查：pm path <pkg> / pm list packages -d；修复：从 zip 提取 manager.apk 后 pm install -r，再 pm enable org.lsposed.daemon。
    • ② 共享锁未释放：LSPosed 与 Vector 共用 /data/adb/lspd/lock 的 flock 单例锁；u:r:ksu:s0 上下文下 rm/chcon/restorecon/chmod 全无效，唯一解法是扫 /proc/[0-9]*/fd/* 用 readlink 命中锁的 pid 并 kill -9 释放 fd。
    • ③ 统一清残留 + 直拉 daemon：两框架共用同一套清残留，不再为 Vector 单独走 service.sh——杀 zygisk-ptrace64 / vectord / lspd / 两侧 zygiskd64-zygisk_lsposed / zygiskd64-zygisk_vector，释放锁，rm -rf /data/adb/neozygisk，拉起 NeoZygisk monitor（zygisksu/post-fs-data.sh）与选中目标 daemon，setprop ctl.restart zygote 验证。daemon 一律 app_process -Djava.class.path=<模块>/daemon.apk -Xnoimage-dex2oat /system/bin --nice-name=<daemon> <Main> 直拉，必须带 -Xnoimage-dex2oat（避开 Android 17 ART 的 dexoptanalyzer SIGSEGV）。恢复页单选「选中谁就修谁」。
  • 次要原因（旧版）：软重启会 stop → 重放 → start。Vector 的旧 daemon 是 detached 进程，杀不掉；service.sh 又起一个新的 → 两个 daemon 抢同一服务 → 崩溃。
  • 处理：禁用 Vector → 软重启 → 启用 Vector → 再软重启一次。
  • 同类风险：任何"自带守护进程 + 在 service.sh 启动"的模块都可能双开。判断：ps -A | grep -c <daemon名>，>1 就是撞了。

6.2 状态 1（漏洞提权，现在能做什么）

这是手段，不是分支。提权后 su -c ksud -V 打出来的是哪一家，这台机器就属于哪一家（8E5 实测是 FinaSU）。
能做 不能做
删预装、改 hosts（重启还原） 改物理分区（锁 BL 下 AVB 失败 = 硬砖，无 fastboot 救援）
抓日志、备份、跑脚本（最安全的用途） 刷 boot / init_boot
备份 init_boot / abl（做任何实验前先做） 依赖真实重启的模块
装模块 + ksud soft-reboot 挂载 换 root 分支（见下）

为什么换不了分支：漏洞链在内存里 insmod 一份预编译、版本固定的 .ko，管理器只是客户端。客户端必须和内核里的服务端同协议，所以——用哪一家不由你选，由漏洞链里那份 .ko 决定。装成别家的管理器只会显示「未安装」。

怎么知道你这条链是哪家：看 su -c ksud -V、ls /data/adb/ksu/bin，再对 2.3 分支速查卡 的特征。8E5 的链是 FinaSU 系（有 folkzygisk、ksud 带 zygisk/sui/boot-hide 子命令）。

6.3 要不要走到状态 2（假回锁 → 永久 root）

⚠️ 全文风险最高的一步。解锁方式不是官方解锁码，而是改写 ABL 引导 + 新建 efisp 分区。失败后果：卡 bootloader / 无 fastboot / 只能走售后或 EDL。

留在状态 1 就够，如果你的目标只是：去广告、删预装、抓包调试、临时备份。

必须走到状态 2，如果你要：长期跑 Vector + 完整模块栈、过银行检测（临时 root 每次开机重来，模块栈无法维护）。

7. 使用者的六条纪律

  1. 先备份，再动手：init_boot / abl 双槽 + GPT，导出到电脑。零风险，不可跳过。
  2. 一次只改一个变量，改完重启验证，出问题立刻回退。
  3. 只从项目官方 GitHub Releases 下载。TG 整合包、网盘短链是投毒重灾区；root 模块等于给系统装 ring0 后门。装之前看三件事：有仓库吗？近半年有提交吗？写了兼容范围吗？三条缺两条就别装。
  4. SELinux 保持 Enforcing。要求 setenforce 0 才能工作的模块一律打问号。
  5. 别追求 STRONG 完整性，也别为了"更保险"堆叠模块——每多一个就多一个冲突源。
  6. 接受边界：变砖、丢数据、保修失效、被风控拒付都是真实后果。高价值支付操作用未 root 的第二台设备。
